# Kiro facts this project relies on

Checked on 2026-11-11 against https://kiro.dev/docs. Re-check before the Dec 4 submission; Kiro ships often. Anything marked **unverified** must not become a hard error in Exorcist.

| Feature | Doc | Verified facts we use | Unverified / open |
|---|---|---|---|
| Steering | https://kiro.dev/docs/steering/ | Lives in `.kiro/steering/`. Defaults `product.md`, `tech.md`, `structure.md`. Front matter must be the first content in the file. `inclusion: always` (default), `fileMatch` + `fileMatchPattern` (string or array), `manual` (`#name` in chat), `auto` (needs `name` + `description`). File refs: `#[[file:path]]`. CLI V3 supports all four modes; CLI V1/V2 only load `always`. Workspace steering overrides global. | Whether unresolved `#[[file:]]` refs are reported as warnings by the CLI (page says a visible marker is left). |
| Hooks | https://kiro.dev/docs/hooks/ and https://kiro.dev/docs/hooks/types/ | File: `.kiro/hooks/<id>.json`, shape `{ "version": "v1", "hooks": [ ... ] }`. Hook keys: `name` (req), `description`, `trigger` (req, PascalCase), `matcher`, `action` (req: `{type:"command", command}` or `{type:"agent", prompt}`), `timeout` (seconds, default 60, 0 disables), `enabled`, `confirm` (Stop + command only; `question`, `options[{id,label,run}]`, `confirmCommand`). Command actions run in the project root and receive session context as JSON on STDIN; for file-save events it includes the saved file path. Verified trigger names: `SessionStart`, `SessionEnd` (V3), `PreToolUse`, `PostToolUse`, `PostFileSave`, `Stop`, `PreCompact`, `PostCompact`. `agentSpawn` is the CLI 2.x name, replaced by `SessionStart`; `AgentSpawn`/`agentSpawn` still accepted as compatibility spellings. Matcher for tool events: tool ID, category tag, `@mcp`, `@<server>`, wildcard, or regex; for file events: regex on path. File triggers fire only for agent-made changes. | Exact PascalCase names for Prompt Submit, Post Tool Use display, File Create/Delete, Pre/Post Task Execution were **not shown** in the fetched page text. Exorcist treats unknown trigger names as a *warning*, never an error. The STDIN key name that carries the saved file path is **not documented**; `scripts/hooks/analyzer-saved.mjs` searches all string values instead of assuming a key. |
| Custom agents | https://kiro.dev/docs/custom-agents/configuration-reference/ | Workspace agents in `.kiro/agents/*.json` (or `.md` with YAML front matter). Fields: `name` (optional, from filename), `description`, `prompt` (inline or `file://` relative to the config), `mcpServers`, `tools` (category tags `read`,`write`,`shell`,`web`,`subagent`; `@mcp`, `@builtin`, `@<server>`, `@<server>/<tool>`, `*`), `permissions.rules[{capability, match, effect: allow|ask|deny, exclude}]`, `excludedTools`, `resources` (`file://` with globs, `skill://`, knowledge-base objects), `hooks` (inline array), `includeMcpJson`, `includePowers`, `model`, `welcomeMessage`. **Limits (CLI 3.1.0+, IDE 1.4.86+):** max 32 `file://` files, 100,000 chars total, 50,000 chars per file, files over 1 MiB skipped; loading stops at the limit. **Legacy CLI 2.x fields not applied by V3:** `allowedTools` (migrate to `permissions`), `toolsSettings`, `toolAliases`, `keyboardShortcut`. `/upgrade-agent` converts 2.x configs. | Whether `name` mismatching the filename is an error or just ignored. Whether a `file://` glob that matches zero files is reported. |
| Specs | https://kiro.dev/docs/specs/ | `requirements.md` (or `bugfix.md` for bug fixes: current / expected / unchanged behavior), `design.md` (architecture, components, sequence/data flow, error handling, testing strategy), `tasks.md` (discrete trackable tasks; Kiro builds a dependency graph and runs independent tasks in waves). Feature specs can be requirements-first or design-first. | The fetched page did not show the exact Markdown headings or the `- [ ] 1.` / `_Requirements: 1.1_` task syntax. The format used in `.kiro/specs/core-engine/` follows Kiro's generated specs as commonly seen; **confirm by opening the spec in the Kiro IDE and checking that tasks render as runnable.** Exorcist's spec-drift rule only parses checkbox lines and file paths, so it tolerates heading differences. |
| Crew apps | https://kiro.dev/docs/crew/apps/manifest/ and https://kiro.dev/docs/crew/apps/build-first-app/ | `app.json` at app root. Required: `name` (kebab-case regex `^[a-z0-9]+(?:-[a-z0-9]+)*$`), `version` (semver), `displayName`, `description`. Resources: `agents[]`, `skills[]`, `sops[]`, `mcpServers{}` (the key is `mcpServers`, not `mcp`). `crons[{name, every | cron_expr, message, agent?, enabled?}]`. `ui.entry`, `ui.pages[{route,label,icon?}]`. `permissions.api[]` is the only enforced permission today. Layout: `app.json`, `agents/*.json`, `skills/<name>/SKILL.md` (front matter `name`, `description`, `triggers[]`, `always`), optional `ui/` (Vite) and `backend/`. Install: `POST http://localhost:5476/api/apps/install {"source": "/abs/path"}` then `POST /api/apps/<name>/enable`; dev mode `kirocrew app dev <name>`. Agent JSON inside Crew apps uses `name, model ("auto"), description, prompt, tools (["@kirocrew-core"])`. | Whether Crew agent JSON accepts the full custom-agent schema (`permissions`, `resources`). Whether the Kiroween "Best Kiro Crew App" bonus accepts a Crew app that lives inside this monorepo or needs its own repo (ask organizers). |

## How Exorcist uses this table

Each Exorcist analyzer rule carries a `source` URL from this table. Rules whose facts sit in the "Unverified" column emit severity at most 0.3 and are labeled "warning" in output. Rules from the "Verified" column may emit up to 1.0.
